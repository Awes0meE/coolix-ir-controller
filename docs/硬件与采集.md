# 硬件与采集

实测组合：USB-B 接口 UNO R3 兼容板（CH340，VID/PID `1A86:7523`）、1838B 5V 接收模块、带 MOS 驱动/限流的 940nm 发射模块，以及 YORK RG94A/BGEF 原遥控器。板上上传签名兼容 ATmega328P，未据此确认芯片生产厂商。UNO R4 不适用 `arduino:avr:uno` 配置。

## 接线

断电后改线，按模块丝印核对，不依赖照片中的左右位置。

| 模块 | 引脚 | 连接 |
| --- | --- | --- |
| 1838B 接收 | S | UNO D2 |
| 1838B 接收 | 中间供电脚 | UNO 5V |
| 1838B 接收 | − | UNO GND |
| 带驱动发射模块 | IN | UNO D3，仅控制信号 |
| 带驱动发射模块 | +5V | 匹配模块电流需求的稳压 5V 电源 |
| 带驱动发射模块 | GND | 电源负极，与 UNO GND 共地 |

本次 3W 模块商品页标称 700mA；推荐独立 5V、至少 1A 电源供发射模块。UNO 仍由 Mac USB 供电，外部 +5V **不要连接**到同时由 USB 供电的 UNO 5V 脚。裸红外 LED 需要另行设计限流与驱动，不能直接套用此接线。

历史验证中按设备持有人的明确选择，曾由 UNO USB 的 5V 为发射模块供电并成功短发。未测量供电裕量、峰值电流或连续发送温升，不能把成功单发当作大功率模块的通用供电证明。发射控制空闲 LOW，波形载波设置 38kHz、占空比设置 30%；接收包络不能测量实际载波频率。

## 采集流程

先停 Web 控制服务并关闭其他串口程序，再编译上传：

```sh
sh scripts/arduino.sh compile --fqbn arduino:avr:uno sketches/ACCapture
sh scripts/arduino.sh upload --fqbn arduino:avr:uno \
  --port /dev/cu.usbserial-XXXX sketches/ACCapture
sh scripts/arduino.sh monitor --port /dev/cu.usbserial-XXXX --config baudrate=115200
```

| 串口输入 | 含义 |
| --- | --- |
| `c` | 单次采集，60 秒窗口 |
| `a` | 连续采集 |
| `x` | 停止采集 |
| `p` | 读取 D2 空闲电平 |

收到 READY 后等约 1 秒，对准接收头短按一个按钮。不同按键之间留出至少 3 秒，并记录遥控器模式、温度、风量和按键。采集固件始终将 D3 保持 LOW，不发射。

`RAW_US` 从第一段 mark 开始，mark/space 交替，单位为微秒，不含头尾静默；至少 120ms 静默结束捕获。缓冲区 640 项、16-bit tick。`OVERFLOW`、`TIMEOUT` 和 `TOO_SHORT` 不能作为完整可重放样本。原始日志可能有上电串口杂字节和 CRLF，因此按原字节保留。

```sh
.venv/bin/python scripts/analyze_capture_log.py \
  logs/2026-11-01-remote-characterization.log --output .runtime/analysis.json
```

完成采集后重新上传 `ACStateControl`，再恢复 Web 服务。`ReceiveProbe` 仅为普通遥控器诊断示例；`ACSendOnce` 是最初 25°C 单次试验程序，都不是当前 Web 固件。
