# 网页部署与主机迁移

## 配置与启动

先完成 README 中的硬件接线、固件上传和 Python 依赖安装。复制 `.env.example` 到私有的 `.runtime/controller/service.env`：

```sh
export IR_SERIAL_PORT=/dev/cu.usbserial-XXXX
export IR_PUBLIC_ORIGIN=https://controller.example.com
```

串口以 `.venv/bin/python -m serial.tools.list_ports -v` 的实际结果为准。`IR_PUBLIC_ORIGIN` 必须与浏览器地址的协议、主机名和端口一致；只做本机测试可保留默认 `http://127.0.0.1:8768`。

| 配置 | 默认 | 作用 |
| --- | --- | --- |
| `IR_SERIAL_PORT` | 空 | UNO 串口，必须指定才能连接 |
| `IR_PUBLIC_ORIGIN` | `http://127.0.0.1:8768` | 允许的公开 Origin / Host |
| `IR_DATA_DIR` | `.runtime/controller` | 凭据、会话和状态数据库目录 |
| `ARDUINO_CLI` | 项目内工具，其次 PATH | Arduino CLI 可执行文件 |
| `CLOUDFLARED` | 项目内工具，其次 PATH | cloudflared 可执行文件 |

`controller/run.sh` 加载 `service.env`，然后启动绑定 `127.0.0.1:8768` 的单实例 Uvicorn。不要增加 worker 数或同时运行第二个串口服务。跨平台手工启动可使用 `python -m uvicorn controller.server:app --host 127.0.0.1 --port 8768`，但本项目的后台安装器面向 macOS，其他平台尚未验证。

首次启动创建随机访问码，保存在私有 `access-code.txt`；`credentials.json` 存放加盐的 PBKDF2 校验信息。浏览器会话保留 30 天，“锁定控制器”只撤销该会话。公网 Cookie 使用 Secure / HttpOnly / SameSite=Strict，写接口校验 Origin 和 CSRF。未登录不能读取空调状态或发送控制。

## 定时开关机与回家预制冷

首页的“一键预制冷”立即发送制冷 24°C、大风，收到发送回执后计时 10 分钟，再发送除湿 24°C、自动风量。除湿会持续运行，直到用户另行调整或关机；不自动关机，也不根据室温提前切换。

“定时开关机”支持倒计时（分钟）或指定日期时间，均为一次性任务。指定时间按手机当前时区显示，发送到服务器时转换为绝对时间。定时开机保存添加时的目标模式、温度和风量，之后调整页面目标不会修改已保存的任务。任务最多提前 30 天设置，同时最多 12 个待执行任务。

任务存入原 `controller.sqlite3` 的新增 `schedules` 表。关闭网页、锁定控制器或手机退出浏览器后，Mac 仍负责计时；不新增后台服务。未来任务在服务重启后保留，启动时已到点的任务标为错过；运行中因睡眠等原因落后超过 30 秒的任务也不补发。USB 离线或发送结果不明时记录失败或未确认，不自动重试。

取消预制冷只取消后续除湿切换，不发送关机。有效的手动控制或到点的定时开关机接管时，会先持久化取消后续预制冷阶段，避免其重新开机或覆盖新设定。独立定时任务仍保留，需要时在列表中分别取消。同一时刻到点的任务共用串口锁和 2 秒发送间隔。

手机可通过浏览器“添加到主屏幕”保存入口。保留登录后，从图标打开即可点“一键预制冷”；登录过期时仍需输入原访问码。服务器须保持登录、接电、联网和 USB 连接。

## HTTP 接口与数据模型

接口仅供已授权的控制页使用。所有 POST 要求 `Content-Type: application/json` 和允许的 `Origin`；除登录外还要求会话 Cookie 与 `X-CSRF-Token`。控制指令和任务创建另要求唯一 `X-Request-ID`（16–80 个字母、数字、下划线或连字符）。同一编号、相同请求返回已保存结果；同一编号改换内容返回 409。客户端遇到网络错误不自动重发。

| 路由 | 请求 / 结果 | 鉴权与副作用 |
| --- | --- | --- |
| `GET /health` | HTTP 服务健康 | 公开；不查询空调反馈 |
| `POST /api/login` | `code`；返回会话与 `csrf` | 验证访问码；不发红外 |
| `GET /api/session` | 登录状态与 `csrf` | 需要登录 |
| `POST /api/logout` | 空 JSON | 只撤销本次会话；不取消已安排任务 |
| `GET /api/state` | `state`、`board`、`history`、`cooldown_ms`、`schedules`、`server_time` | 需要登录；不发红外 |
| `POST /api/command` | 状态或按键 `payload` | 用户立即控制，成功/未知结果持久化 |
| `POST /api/schedules` | `kind=timer`、`due_at`、`payload`，或仅 `kind=precool` | 定时任务只保存；预制冷立即发送第一阶段 |
| `POST /api/schedules/{id}/cancel` | 空 JSON；返回任务状态 | 取消尚待执行部分，不发送关机 |

定时任务的 `due_at` 为 Unix 时间秒，须在服务器时间 5 秒后至 30 天内；这项最小预约提前量与 **2 秒发送间隔**不同。`payload` 为 `{"action":"button","button":"power-off"}`，或含 `action=climate`、`mode`、`temperature`、`fan` 的开机设定。预制冷固定使用 `{"kind":"precool"}`，不接受其他参数。

鉴权失败返回 401，Origin / CSRF 不符为 403，不支持的目标或时间为 422，发送间隔未结束为 429。已有预制冷正在进行或达到 12 个活动任务上限时返回 409。`board.min_interval_ms` 来自固件 STATUS；新固件应为 2000，旧固件未报告时为 `null`。

四张表共用私有 `controller.sqlite3`：`meta` 保留最近发送设定与序号；`commands` 保存请求指纹及发送结果；`sessions` 保存会话校验值与有效期；`schedules` 保存任务编号、原请求指纹、类型、阶段、目标指令、到期时间、创建时间、状态与说明。新增表不重建前三张表，也不重新生成访问码。

## 调度与恢复

`controller/server.py` 在现有后端进程内启动状态查询和定时线程；`controller/scheduler.py` 每秒检查到期任务，与手动操作共用 `Controller` 的可重入锁和发送间隔。执行前先将任务从 `pending` 持久化为 `running`，再经原命令防重发流程独占串口发送。

成功的普通定时任务转为 `completed`。预制冷第一阶段发送完成后，将同一任务更新为 `dry` 阶段，保存除湿目标并预约回执后 600 秒；第二阶段成功后才完成。失败为 `failed`，发送结果无法确认则为 `unknown`；取消为 `cancelled`。服务启动时将遗留 `running` 标为 `unknown`，将已到期 `pending` 标为 `missed`，均不重放。未到期任务保留，后续到点正常执行。

手动控制和定时开关机在发送前先持久化取消尚待执行的预制冷阶段，避免接管时发生崩溃，重启后又发送旧阶段。网页刷新只读状态，不能重新启动预制冷或创建重复定时任务。

## Cloudflare Tunnel

1. 在自己的 Cloudflare 账号创建**独立隧道**，不要把不同物理设备的服务随意挂成同一条隧道的负载均衡副本。
2. 安装官方 `cloudflared`，例如在 Mac 上运行 `brew install cloudflared`。脚本也支持项目内 `.tools/cloudflared/cloudflared`。
3. 把这条隧道的纯连接令牌写入 `.runtime/controller/tunnel-token`，文件权限设为 0600。令牌不写在源码、命令历史、公开文档或进程参数中。
4. 启动 `sh controller/tunnel.sh`。在 Cloudflare 添加“已发布的应用程序”，选择自己的域名，例如 `controller.example.com`，服务地址填写 `http://127.0.0.1:8768`。
5. 确认 `service.env` 的 `IR_PUBLIC_ORIGIN` 与正式 HTTPS 域名相同，然后启动或重启本机服务。通过正式域名登录验证。

隧道只对外发布端口 8768 的应用。`/health` 只表示 HTTP 服务健康，不代表 UNO 在线；登录后的页面才显示控制器状态。网页不离线排队或自动重试指令。

## macOS 后台运行

```sh
.venv/bin/python scripts/install_controller_services.py --tunnel
```

安装两个当前用户 LaunchAgents：

- `com.66ccff.ir-controller`：网页与串口服务。
- `com.66ccff.ir-controller-tunnel`：这条独立隧道。

登录后自动启动，退出后重启；不是开机未登录就运行的系统服务。安装器按项目当前路径写 plist，不覆盖内容不同的既有服务。项目路径改变后需要重新安装。

服务用 `caffeinate -i` 防止运行时自动空闲睡眠；主动睡眠、合盖导致的睡眠、关机、注销或 USB 断开仍会让控制不可用。日志在 `.runtime/controller/com.66ccff.ir-controller*.log`。

重启应用（不会发红外）：

```sh
launchctl kickstart -k gui/$(id -u)/com.66ccff.ir-controller
```

停止并释放串口：

```sh
launchctl bootout gui/$(id -u)/com.66ccff.ir-controller
```

恢复已安装的应用：

```sh
launchctl bootstrap gui/$(id -u) "$HOME/Library/LaunchAgents/com.66ccff.ir-controller.plist"
```

上传固件前停服务，上传后再恢复。不要同时运行 Arduino monitor。

## 迁移到 MacBook Server

域名、隧道和令牌可以沿用，不需要重新生成。UNO 必须插到目标主机，发射头仍能照到空调；切换时只保留一台带 UNO 的活动服务。

1. 在旧主机停止两个服务：

   ```sh
   launchctl bootout gui/$(id -u)/com.66ccff.ir-controller-tunnel
   launchctl bootout gui/$(id -u)/com.66ccff.ir-controller
   ```

2. 在目标主机 clone 仓库并使用 Python 3.11 重新建立 `.venv`，安装锁定依赖和 cloudflared，不复制旧虚拟环境。UNO 已有匹配固件时无需重刷；固件协议或间隔发生变化时才安装 Arduino 工具、编译并上传。
3. 通过 SSH/SCP 等私有方式复制整个 `.runtime/controller/`。复制数据库时旧服务应已停止。若使用自定义 `IR_DATA_DIR`，同时复制实际数据目录并修改目标主机配置。
4. 修改目标主机的 `service.env`：更新实际串口；保留原来的 HTTPS Origin。私有目录权限 0700，令牌/访问码/凭据/数据库权限 0600。
5. 旧主机两个 plist 移出 `~/Library/LaunchAgents` 后妥善保留，避免旧主机下次登录又连接；其他应用的隧道和服务不动。
6. 在目标主机执行安装器 `--tunnel`，登录原域名确认“控制器在线”，再安排一次明确目标的实物验证。

复制的内容分别用于：

| 文件 | 保留的内容 |
| --- | --- |
| `tunnel-token` | 原来的 Cloudflare 隧道连接身份 |
| `service.env` | 域名和设备配置，串口需按新主机修改 |
| `credentials.json`、`access-code.txt` | 原网页访问码 |
| `controller.sqlite3` | 最近发送设定、历史、请求编号和现有登录会话 |

历史设定仍然只是发送记录，不代表搬动后的空调实际状态。迁移过程不需公开任何私有运行文件。

## 常见问题

- **网页可打开但离线**：检查串口配置、USB 连接及其他程序是否占用串口。`/health` 正常并不能排除这些问题。
- **Host / 来源校验失败**：核对 `IR_PUBLIC_ORIGIN`，不要为排错直接删除鉴权和 Origin 校验。
- **发送结果未确认**：先观察空调，服务不会自动重放；不要连续点击尝试补发。
- **登录码在哪里**：默认 `.runtime/controller/access-code.txt`；指定 `IR_DATA_DIR` 时在对应目录。
- **发送间隔仍被固件拒绝**：查询登录后状态中的 `board.min_interval_ms`，应为 2000；只改后端不会替换 UNO 中的旧固件。
- **框架重载是否发射**：不会补发错过的任务，已安排的未来任务仍会在到点时执行。但重新打开串口可能复位 UNO，所以日常不启用开发自动重载。
